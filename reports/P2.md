# P2 Backend additions (all additive)

## Key points
- `backend/precompute_frames.py` writes `cache/frames/palm_jumeirah/<year>/{bands.npz, meta.json}` on one 30 m EPSG:3857 grid (267 × 298 px, 3.5 MB in total).
  - Sensor is chosen by acquisition date: Landsat 7 before 1 Jun 2003, Landsat 5 after.
  - Window: May ± 45 days for Landsat, January ± 30 days for Sentinel-2. Best-day picker on the real AOI valid %, retries with backoff.
  - Kept: 2000-05-19 L7 (99.7%), 2001-05-22 L7 (100%), 2003-05-28 L7 (98.7%), 2008-05-17 L5 (100%), 2018-01-14 S2B (90.0%), 2024-01-23 S2B (99.3%).
  - Dropped: 2002 (51.7% valid, under the 60% rule). 2004, 2005 and 2006 (no Landsat 5 scene over Dubai for April–June in Planetary Computer: `NoScene`).
- `GET /api/compare?preset&y1&y2&index` loads two frames into xarray and calls the **unchanged** `change.run_change`. It writes `cache/presets/palm_jumeirah__<y1>_<y2>/` and returns an Analysis.
  - Additive fields: `context`, plus `scene_*.scale/offset` from the frame metadata.
  - A missing year returns 422 with the list of years available.
- `context` on preset Analyses comes from `backend/presets.json`. `GET /api/presets/{id}` attaches it (one-line additive edit in `main.py`).
- `POST /api/chat/stream` (SSE) emits `plan` (rule router, 0 ms, with `fly_to`), `progress`, `analysis`, `cards` and `done`. Any exception becomes a friendly `cards` event. `/api/chat` is unchanged.
- `GET /api/config` returns `arcgis_key` (from `.env`), `basemap_order`, `attributions`, `model`, `online` and `frames`. `GET /api/frames/{pid}` lists the bank.
- Year rules:
  - Both years in the bank: compare. One missing: list what exists.
  - The window does not cross a milestone: note chip.
  - No preset and a pre-2016 year: "No precomputed history for this place; showing the nearest preset."

## Suggestions for the team (frozen files, not changed)
- `main.load_analysis`: accept only ids matching `^(live:[0-9a-f]{10}|presets:[a-z0-9_]+)$`. On Windows a drive-letter id could escape `cache/`. Low risk, since the server binds to localhost and reads only `result.json`.
- `agent.measured_card` writes "+0%" for small changes, and rounds 0.05 to "0.1 km²" next to the exact stats. Consider 2 decimals under 1 km².
- `agent.interpretation`: the guard allows any number found in FACTS. In one run the model called the 47.9 km² gross loss "a reduction", while the net is 47.6. Consider allowing only net and valid %.
- `agent._ground` keeps an LLM month for a year-only question (2018 → 2018-01-01). Research §2.4 says to reuse the same month for both dates.
